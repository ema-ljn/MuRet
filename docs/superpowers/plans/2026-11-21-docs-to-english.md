# Docs to English: translation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every doc in the repo in English, without losing a single address, id, number or link, and without breaking the
code citations that point into the research.

**Architecture:** one PR per group of docs, in order of how often agents and people read them. A script checks that each
translated file keeps what must not change; another rewrites links and code citations when a file or section is
renamed. Code comments are not part of this plan: the client refactor's comments PRs translate them
([refactor plan](2026-11-20-client-architecture-refactor.md), "The comments PRs").

**Tech Stack:** Markdown, Python 3 with the standard library and `unittest`, GitHub Actions.

**Decision:** Emanuel, 2026-11-21: branches, PR descriptions, comments "and everything" in English; on the decision card
he chose "comments and docs": new docs in English from now on and existing docs translated in their own PRs.

## Global Constraints

- New docs are written in English from 2026-11-21 on. A doc touched by a port PR before its group is translated stays in
  its current language (no half-translated files).
- Translation changes language, not content: no fact, number, decision, date or attribution is added, dropped or
  "improved". A wrong fact found while translating is reported, not fixed in the same PR.
- What never changes: addresses (`0x4e2b10`), ids (`Q-C591`, `P-C20`, `D-C12`, ADR numbers), code identifiers, commands,
  paths of code files, commit hashes, and quotes from the binary or the original's data.
- Numbers switch to English notation: `1.418` → `1,418`, `1,3 %` → `1.3%`, `164 mil` → `164k`. The script checks the
  count of digits, not the separators.
- Quotes from Emanuel are translated; the Spanish original may follow in parentheses only when the wording itself
  matters.
- Files and folders get English names (`docs/learning/ola-2-sockets.md` → `docs/learning/wave-2-sockets.md`), with every
  link in the repo rewritten in the same PR. Numbered prefixes stay (`06-` in the research), so citations keep a stable
  key.
- Chat with Emanuel stays in Spanish; that is not a doc.
- At most 3 agents in parallel (Emanuel, 2026-11-19), counting the port's and the refactor's.
- PR titles `docs: translate <group> to English`; commits and descriptions in English.

## Review Focus

- A Spanish thousands separator read as a decimal (`1.418` translated as `1.418` instead of `1,418`): the digit count
  passes, so the reviewer reads every number in tables.
- A research section renamed while a code comment still cites the old title (`// 04-protocolo § tabla de heads`): the
  citation rewrite must find every one of the 674 `§` citations in `Client/`, and the check must fail on a citation that
  points to no heading.
- A link to a renamed file from outside the group (another doc, `ci.yml`, a script, a test that reads a doc path):
  `rewrite_links.py` must cover the whole repo, not just the group.
- A quote from the original's data or the binary (Korean, Windows-1252 text, a message of `main.exe`) translated by
  mistake: those stay byte for byte.
- A generated file (the reference TSVs, `coverage/*.json`) translated by hand: it must be regenerated by its tool, never
  edited.

- **T7 before AR0.2**, because AR0.2 adds columns to the reference (`module`, `anchor`): they land in an English schema.
- **T4 and T5 after AR0.2**, because renaming research sections rewrites code citations, and that commit must go into

### T0: the tools

**Files:**
- Create: `tools/docs/check_translation.py`, `tools/docs/test_check_translation.py`
- Create: `tools/docs/rewrite_links.py`, `tools/docs/test_rewrite_links.py`

**Interfaces:**
- Produces: `check_translation.py --base <ref> --head <ref> [--renames <old=new>...]`: for each Markdown file changed
  between the refs (followed through renames), it compares the multiset of addresses (`0x[0-9a-fA-F]{4,8}`), of ids
  (`[QPD]-C\d+`, `ADR \d+`), of commit hashes, of fenced code blocks (byte for byte) and of table rows per table, and the
  count of digits outside them; it checks that every relative link and anchor resolves. Exits with 1 and lists each
  difference.
- Produces: `rewrite_links.py --map <renames.tsv>`: `renames.tsv` has `kind` (`file` or `section`), `old`, `new`; it
  rewrites Markdown links and anchors across the repo, paths in `*.yml`, `*.py`, `*.cmake` and `CMakeLists.txt`, and
  `// <file or number> § <section>` citations in `Client/` comments (`04-protocolo.md § …` and the short `02 § …`). It prints what it changed and what it could not resolve.

- [ ] **Step 1: the tests:**
  - `test_dropped_address_fails`: the translation loses one `0x4d3200` → 1 and the address.
  - `test_changed_code_block_fails`: a fenced block differs by one character → 1.
  - `test_thousands_separator_passes`: `1.418 archivos` → `1,418 files` → 0.
  - `test_broken_anchor_fails`: a link to `#los-módulos-uno-por-uno` after the heading became English → 1.
  - `test_rewrite_section_citation`: `// 04-protocolo.md § tabla de heads` with a section rename → the new title; the
    code on the line is untouched.
  - `test_rewrite_link_outside_group`: a link from a file outside the renamed group is rewritten too.
- [ ] **Step 2:** they fail; Step 3: the two scripts; Step 4: they pass.
- [ ] **Step 5:** a CI step in the `includes` job runs the tests and, on PRs titled `docs: translate`,
  `check_translation.py` against the base.
- [ ] **Step 6:** commit `docs: add translation check and link rewriter`.

### T1 to T6: one group per PR

Each group follows the same steps:

- [ ] **Step 1:** list the group's files and decide the English file names; write `renames.tsv` (files and, for the
  research, sections).
- [ ] **Step 2:** translate, at most 3 agents in parallel, each with whole files (never half a file). Each agent gets
  these Global Constraints and the glossary below.
- [ ] **Step 3:** `rewrite_links.py --map renames.tsv` and `git mv` for the renames.
- [ ] **Step 4:** `check_translation.py` at 0; the docs formatting job green; for T4 and T5, also
  `check_comments_only.py` at 0 on the rewritten citations and the squash recorded in `.git-blame-ignore-revs`.
- [ ] **Step 5:** a second agent reads the diff against the original, table by table, looking at numbers and at anything
  that sounds like a new claim.
- [ ] **Step 6:** commit `docs: translate <group> to English`.

**Per group:**

- **T1:** CODING_RULES §7 and §9 already say everything goes in English; the translation keeps the rules exactly,
  including the dates and who decided. `CLAUDE.md` and `AGENTS.md` keep their structure (other tools read them).
- **T2:** `docs/learning/ola-*.md` → `wave-*.md`; ADR files keep their number (`0016-western-text-in-windows-1252.md`).
  `PROGRESS.md` keeps its name.
- **T3:** the five specs get English names (`2026-10-30-cliente-design.md` → `2026-10-30-client-design.md`).
- **T4 and T5:** the research files keep their number and get an English slug (`06-render-escenas-y-ui.md` →

  rewritten in the same PR. T5 can be three PRs (06, 07 and
  08), because 06 alone is 1.5 MB.
- **T6:** plan files get English names; their checkboxes and commit references stay.

## Messages in code

CODING_RULES §7 now asks for log and error messages in English. Changing an existing message changes the tests that
assert on it, so it is not a comments PR and not part of this plan's PRs. It goes module by module, after each module's
comments PR in the refactor, with its tests in the same PR. Strings that reproduce the original's output (the crash
report, messages copied from `main.exe`, text from `Data\`) stay as they are.
