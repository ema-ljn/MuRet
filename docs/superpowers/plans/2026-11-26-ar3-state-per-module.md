# AR3, state per module: detailed plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every global of the original that MuRet ports has one home, a field of one struct owned by one module, and a
registry says which. A handler receives only the parts of the state it touches. `WorldRuntime` stops being the bag
every module reaches into. No byte of behavior changes.

**Architecture:** AR3.1 builds the registry (`globals.tsv`, generated by the reference from the data citations), moves
the types every module shares (the actor, the player, the current map) down to `game/Kernel`, and gives the state a
composition root, the `GameContext`, with `Hero()` and the character class. AR3.2 moves the first states out of
`WorldRuntime`: the ones a single module uses and the ones that already belong to one module. The rest leaves with its
module in AR4.

**Tech Stack:** C++20, CMake, GoogleTest, Python 3 (standard library, `unittest`), GitHub Actions.

**Spec:** [`docs/superpowers/specs/2026-11-20-client-architecture-design.md`](../specs/2026-11-20-client-architecture-design.md),
"State: from the `.bss` in two aggregates to parts per module", the epic in the master plan
([`2026-11-20-client-architecture-refactor.md`](2026-11-20-client-architecture-refactor.md), "Epic AR3"), Task 7 of the
[named-values plan](2026-11-23-named-values.md) and the state split of
[`2026-11-24-crywolf-homes.md`](2026-11-24-crywolf-homes.md). AR2's plan
([`2026-11-26-ar2-protocol-and-dispatch.md`](2026-11-26-ar2-protocol-and-dispatch.md)) needs AR3.1 before its Task 12.

Measured on `main` at 736b5544 (2026-11-26), after AR1.

## Global Constraints

- No PR changes behavior. The behavior golden (`tests/characterization`) and every current test and golden must stay
  identical on Linux and Windows, in Debug and `math-release`. A difference is a refactor bug, not a golden to
  regenerate (`superpowers:systematic-debugging`).
- These do not change: the order of the original's calls and of `rand()` calls, the bytes the client writes, the moment
  each reset clears its fields, and what a field holds before its first write.
- One global moves at a time, with the golden green (the `refactoring` skill, *Encapsulate Variable*).
- What is contiguous in the original is not split: `TooltipLines` (Q-C591), `CharacterBalloons` (Q-C1503) and every
  block one reset function clears together.
- Titles and branches: `refactor(AR3.m): …` on `refactor/ar3.m-<topic>`; the generator, `feat(AR3.1): …`. Never `CLn`
  in a scope. CI runs `check_pure_move.py` on every `type(ARn.m)` PR, so no PR of this plan renames a file: a header
  that changes module gets its `target` cell changed, and AR4's moves carry it.
- Everything in English. A comment only when strictly necessary, on one line; keep the `// 0x…` citations, which
  `globals.tsv` reads.
- New scripts: standard library only, `python3 -I`, tests with `unittest`.
- PRs target `main` and may be stacked. Nothing merges without Emanuel's yes (2026-11-26).
- Priority: fidelity, then `docs/CODING_RULES.md`, then `clean-code`, `clean-architecture` and `refactoring`.
- The cloud container builds the client only with the stub recipe and no SDL; GitHub CI is the build and the final word.

## Review Focus

- **One original global behind two MuRet fields.** Moving one of them to a module would split what the original keeps
  in one place, and a write to one would no longer be seen through the other. `globals.tsv` flags every address that two
  declarations cite (Task 1). No task moves a flagged field until its row says which of the two is the home and the
  other becomes a reference to it.
- **A reset that clears several modules' fields.** The original clears contiguous blocks with one `memset` or one loop
  (the world's exit, the return to the selection, `0x42fdc0` for Crywolf). When the fields leave for different modules,
  the reset must still clear all of them in the same step. Each AR3.2 task keeps the reset's current test and adds one
  that checks every moved field after it.
- **The login scene's own world.** `LoginScene` builds a `WorldState` of its own when it has none (`m_localWorld`).
  The `GameContext` must keep that case: Task 3 tests a login with no context and one with the client's.
- **The hero before the world entry.** `WorldRuntime::hero` is 0 until the `F3 03`, and today `Actors()[hero]` reads
  the actor 0 then. `GameContext::Hero()` returns the same actor, with no new check (Task 4).
- **A class compared unmasked.** Where the original compares the whole class byte (the second class in its high bits),
  `BaseClassOf` would change the result. Task 5 keeps those sites on the raw integer, and its test pins one of each.

## How this plan places files

- **A file changes folder only in a move PR**, and AR3 has none. A header whose module changes gets its `target` cell
  changed in `Client/docs/research/coverage/module-map.tsv`; AR4.1 moves `game/Kernel` with `move.py`.
- **A new file is born in the folder it will keep**, `Client/src/game/Kernel/`, takes the namespace `Client::Kernel`
  and gets its map row in the same PR (`confidence` `high`, `why` ending in `(AR3.m)`).
- **A state that leaves `WorldRuntime` keeps its type where it is.** Only the owner changes: the field moves to the
  `GameContext` and `globals.tsv` records the module.

## AR3.1 (design): the registry, the shared core and the `GameContext`

### Task 1: `globals.tsv`

PR `feat(AR3.1): the registry of the original's globals`, branch `feat/ar3.1-globals`. Skills: `python-code-style`,
`python-testing-patterns`.

**Files:**
- Create:
  - `Client/docs/research/scripts/tools/reference_globals.py`
  - `Client/docs/research/scripts/tools/test_reference_globals.py`
  - `Client/docs/research/coverage/referencia/globals.tsv` (generated)
- Modify:
  - `build_client_reference.py`: writes `globals.tsv` with the other tables.
  - `coverage/referencia/LEEME.md`: its columns, beside `trazas.tsv`'s.

**Interfaces (produces):** `globals.tsv`, one row per address of the `.data` (from `0x6c6000`, 06 "the `.data` of the
file") that `Client/src` cites:

| column | holds |
| --- | --- |
| `va` | the address |
| `home` | `Struct::field` of the data member whose declaration cites it, in a header; empty if none does |
| `file`, `line` | that declaration |
| `module` | the map's `target` of `file` |
| `users` | the modules of the other files that cite it, sorted |
| `flag` | `two-homes` if two declarations cite it, `no-home` if none does, empty otherwise |

A declaration is a line of a `.h` inside a `struct` or `class`, ending in `;`, that cites the address in its own
comment or in the comment block right above it. `Struct` is the innermost enclosing one.

- [ ] **Step 1: Write the failing tests** on small headers written in the test:
  - a member with the address in its trailing comment gives its `home`;
  - one with the address in the comment above it, too;
  - a nested struct gives the inner one's name;
  - an address only cited in a `.cpp` gives `no-home`;
  - two members citing the same address give `two-homes`;
  - `0x6b8xxx` (the `.rdata`'s constants) gives no row.
- [ ] **Step 2: Write `reference_globals.py`** with `def build_globals(trazas, sources, module_of) -> list[dict]`, and
  call it from `build_client_reference.py`.
- [ ] **Step 3: Generate it** at the PR's head. At 736b5544 the `.data` has 428 distinct cited addresses, 173 of them in
  headers. Print the counts per `flag` in the PR body.
- [ ] **Step 4: Check.** Run the reference tools' tests (`python3 -I -m unittest discover -s
  Client/docs/research/scripts/tools -p 'test_*.py'`), then push.

## Decisions for Emanuel

1. **Who owns the module states** (Task 3). `game/Kernel` is layer 7 and the modules are layer 9.
   - **A: `Kernel::GameContext` keeps only the shared core** (the actors, the hero, the player, the map) and
     `game/Session/SessionState.h` (layer 10, above every module) holds each module's state by value, both owned by
     `App::GameClient`. `Route<&Fn>` (AR2 Task 12) takes parts from both. No pointers and no upward include; the spec's
     "Kernel owns them" becomes "Session owns them". This plan recommends it.
   - **B: one `GameContext` in Kernel holds everything**, the module states behind forward declarations
     (`std::unique_ptr<Guild::GuildState>`), built and destroyed in `app/`, where every type is complete. It keeps the
     spec's wording, at the cost of one allocation per part and an incomplete type in each accessor.
2. **The shared core moves down to Kernel** (Task 2): the actor, the player and the inventory change module.
   `DarkSpirit.h` and `WorldMap.h` split.
3. **The registry lives with the reference** (`coverage/referencia/globals.tsv`, regenerated with the other tables),
   not hand-written in `Client/`.
